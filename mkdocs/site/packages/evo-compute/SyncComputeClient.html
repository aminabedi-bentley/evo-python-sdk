evo.compute.engine.SyncComputeClient

Blocking sibling of :class:ComputeClient, for scripts and notebooks.

The same catalogue, the same namespace, the same checks -- with the await removed::

client = SyncComputeClient(context)
result = client.geostatistics.kriging.run(source=..., target=..., ...)
grid = result.target.load()

It wraps a :class:ComputeClient and runs its coroutines on the bridge described in :mod:evo.compute._sync, so nothing about validation, resolution or hydration differs between the two paths. The results come back as :class:~evo.compute.outputs.SyncTaskResult, whose loaders block in turn.

Authentication and context creation are outside this client's scope. The context's connection must be usable on the private compute bridge: an open session or other state bound to another event loop raises :class:~evo.compute.exceptions.SyncBridgeError. Close a caller-loop session on its own loop before blocking calls, or use :class:ComputeClient on that connection's event loop instead.

Not a context manager, consistent with :class:ComputeClient. The constructor takes the same arguments and passes them straight through.

Run a task by name and block until it finishes.

The blocking counterpart of :meth:ComputeClient.arun, and defined the same way: :meth:submit, then wait on what it hands back.

Returns:

Type Description

The task's results, with blocking loaders.

Raises:

Type Description
SyncBridgeError

If called from inside the bridge's own event loop, or if the context belongs to a different one.
